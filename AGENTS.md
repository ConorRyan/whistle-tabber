# AGENTS.md

## Working rules

- **Keep the architecture section of this file in sync.** If you change the
  high-level architecture (package layout, data flow, the JS bridge protocol,
  persistence), update "High-level architecture" below in the same commit.
- **Aim for high test coverage broadly.** Add or extend tests for new and
  changed behavior across all layers:
  - Kotlin unit tests in `app/src/test/java/` (JUnit 4 + Robolectric + Turbine
    + coroutines-test); fixtures in `app/src/test/resources/`.
  - Node tests for the shipped JS in `web-tests/` (`node --test`, no npm
    dependencies; fixtures in `web-tests/fixtures/`).
  - Instrumented tests in `app/src/androidTest/java/` for anything that needs
    a real WebView.
  Before finishing a change, run `./gradlew :app:testDebugUnitTest` and
  `(cd web-tests && node --test)`.
- **Instrumented tests run on the emulator only, never on a physical phone.**
  Check `adb devices` first, then run
  `ANDROID_SERIAL=emulator-5554 ./gradlew :app:connectedDebugAndroidTest`,
  and pass `-s emulator-5554` to every adb command. Instrumented tests must
  destroy their `TuneWebController` in `@After` (Chromium caps live
  AudioContexts). To inspect the page of a debug build, forward DevTools and
  use `node scripts/webview-eval.js "<expr>"` (see the script header). AVD:
  `~/.local/share/android-sdk/emulator/emulator -avd Medium_Phone_API_37.0 -no-snapshot-save -no-window`.
- Build with `./gradlew assembleDebug`; release with `./gradlew assembleRelease`.
  Requires JDK 21, Android SDK platform 37, NDK `29.0.14206865` and CMake
  3.22.1 (pinned in `app/build.gradle.kts`; Gradle fetches them into the SDK
  if missing).
  Debug builds install as `<applicationId>.debug` ("… Debug" in the
  launcher, a "D" badge on the icon, `app/src/debug/res/`), beside the release-signed app; target
  that package in adb. Never sign debug builds with the release key.
- Match existing style: 4-space indent, trailing commas, explicit types only
  where the codebase already uses them. Prefer pure, testable functions over
  Android-coupled code.
- **Every user-visible string is translated.** When you add or change a
  string in `values/strings.xml` (including numbers in it, like the
  starter-set size), update `values-fr/strings.xml` in the same change.
  `TranslationsTest` fails on a missing name but can't catch stale text.
- **No AI features, no network.** The app has no INTERNET permission.
- **Data provenance.** Never bundle or use TheSession.org data (its licence
  forbids LLM processing), including as test fixtures. Tunes come from
  O'Neill's 1850 (GPL-2+, credit transcribers via their `Z:` lines) or are
  written by hand. Never copy code from GPL-2.0-only projects
  (e.g. cgrassin/tinwhistletabs).
- Upgrade abcjs only through `scripts/update-abcjs.sh` (pinned version and
  sha256); never edit `app/src/main/assets/web/abcjs-basic.js` by hand.

## High-level architecture

Whistle Tabber is a single-module (`:app`) Android app: Kotlin, Jetpack
Compose (Material 3). Package root: `io.github.conorryan.whistletabber`.
ABC parsing, staff rendering and playback run in a local WebView using a
vendored, unminified copy of abcjs; everything else is native.

```
Compose UI ──BridgeCommand──► TuneWebController ──evaluateJavascript──► whistle-page.js ──► abcjs
    ▲                              │                                         │
    └──────── events: SharedFlow ◄─┴── WebMessageListener "WhistleBridge" ◄──┘ (BridgeEvent JSON)

WebView origin https://appassets.androidplatform.net (WebViewAssetLoader):
  /assets/...                 bundled files (assets/web/, assets/tunes/)
  /sound/<inst>-mp3/<N>.mp3   WAV generated by WhistleSynth (SoundPathHandler)
```

- `web/` — the bridge.
  - `BridgeProtocol.kt`: `BridgeCommand`/`BridgeEvent`/`NoteEvent` + `BridgeCodec`
    (JSON, `"type"` discriminator). It mirrors `assets/web/whistle-page.js`;
    `BridgeProtocolSyncTest` reads the JS source and fails if the two drift.
  - `TuneWebController`: owns one WebView, implements the `render/TunePage`
    port, and queues commands until the page posts `ready` (only the newest
    `Render` is kept).
  - `TuneWebViewHost`: Compose wrapper.
  - `SoundPathHandler`: answers abcjs's soundfont URLs with synthesised samples.
- `render/` — the render cycle, deep behind a small interface.
  - `TunePage`: the port the page satisfies; `TuneWebController` is the real
    adapter, tests use an in-memory fake.
  - `TuneRenderer`: owns "the page shows this ABC with these fingerings":
    render dedupe (same text and transpose only re-draws diagrams), the
    notes → `FingeringEngine` → `DiagramSpec` pipeline, `transposeText`
    request/reply matching (one outstanding request, stale steps dropped),
    optional debounce (the editor), playback mirroring, warnings and errors.
    Each ViewModel owns one; a screen `attach`es its controller, and a
    re-attach re-shows the last request to the fresh page.
- `music/` — pure Kotlin music logic.
  - `Fingering`/`Hole`: six holes, top first, octave 0–2 ("+", "++"), `hard`.
  - `FingeringEngine`: semitones above the whistle's written bottom note →
    fingering. First octave written by hand; second repeats it with "+";
    third octave from the Woodwind Fingering Guide (cited in the file), all
    `hard`. C natural comes from the `CNatural` preference. Out-of-range notes
    fold by octaves when enabled (`Playable.folded`) or report `OutOfRange`.
  - `WhistleKey`: `writtenTonic` (fingering) and `soundingShift` (+12 for
    soprano whistles: whistle music is written an octave below sounding),
    plus `letter` and `register` (high/normal/low) for its name.
  - `NoteNames` (AUTO/LETTERS/SOLFEGE, a tab setting, default AUTO): LETTERS
    and SOLFEGE are each a whole convention, the same in every app language;
    AUTO `resolve`s by the app's language (`R.bool.language_uses_solfege`,
    true in `values-fr`) through `resolvedNoteNames` in `MainActivity`.
    `WhistleKey.label` gives "High G", "Eb", "Low D" or "Sol aigu", "Mi♭",
    "Ré grave"; `noteName` is the key alone.
  - `TabSettings` + `TransposeMode`: SAME_PITCHES recomputes fingerings for
    the chosen whistle; SAME_FINGERINGS keeps the tune whistle's fingerings
    and changes playback pitch (`midiTranspose`).
  - `WhistleSynth`: deterministic whistle tone samples as WAV.
  - `AbcBook`: plain-text ABC operations. `split` (like abcjs's
    `bookParser`: a tune ends at a blank line; file-header `%%` directives
    and fields are copied in after each tune's `X:`), `headers`, `join`
    (renumbers `X:`), `withTitle`, `suggestWhistle(K:)`, and Eskin's
    `%whistle_tab_key` directive (`whistleOf`/`withWhistle`; our extension
    `%whistle_tab_key d low`). `AbcHeaders.problems()` (`AbcProblem`) is the
    one "is this tune storable" check (a `T:` and a `K:`), shared by the
    editor and the import.
  - `KeyChange`: target tonics, steps (−6..+5) and names for rewriting a
    tune into another key.
  - `AbcNotes`: single ABC notes in a major key, MIDI ↔ text. `spellBar`
    writes an explicit accidental on every note of a letter already altered
    in the bar (abcjs's playback scopes bar accidentals by letter and octave,
    its transposer by letter); `parseBar` reads the standard way; `name`
    gives "F♯"/"Fa♯".
  - `TapTune` + `TapDraft`: a tune written by tapping fingerings, stored as
    `FingeringEngine` offsets (null = rest) for a whistle, plus an optional
    `TapTiming` (the `RhythmSetup`, one length in grid units per note, and
    the first bar's length) for a tapped rhythm. `toAbc`: without timing,
    equal quarter notes, `M:4/4`, 4 per bar, 4 bars per line; with it, the
    setup's meter, grid unit and `Q:`, ties across bar lines and for lengths
    one note can't have. Either way the whistle's major key and
    `%whistle_tab_key`; other header lines kept. `parse` reads only these two
    forms back (else null), which is what makes a tune tap-editable — a saved
    timed tune included. `inserted`/`removed` keep the timing (a new note is
    as long as the one before it); `normalized` merges adjacent rests and
    caps the first bar, so a draft always writes and reads the same.
  - `RhythmFit`: rhythm tapped over written notes. `fit`
    turns `Press`es (ms from the first downbeat after the count-in) and a
    `RhythmSetup` (bpm, `Meter`, `RhythmGrid`) into a `Rhythm` (note/rest
    lengths in grid units, a short first bar for a pickup): latency removed,
    onsets snapped by position, gaps under a beat legato. `TapDraft.withRhythm`
    applies it to a draft.
- `scan/` — reading whistle tab from images, pure Kotlin except the loader.
  - `GrayImage`: luma per pixel (0 black–255 white), bicubic `scaled`.
  - `TabReader.read` → `TabReading` (lines of `TabColumn`: six `Hole`s,
    octave from "+" marks, a `Box` in source pixels). Only fingering
    diagrams are read; staff, lyrics and chords are ignored. Two readers, the
    one finding more columns wins: hole by hole (round blobs pooled from
    several ink thresholds, linked into runs of six evenly spaced holes,
    allowing one wider gap between two groups of three, filled/open/half
    split per image) and column first (tall thin blobs of small or blurry
    tab, cut into six cells). Dark-mode images (dark paper) are inverted
    first. No OpenCV.
  - `TabTune`: fingering → note through `FingeringEngine` (plus vented
    `OXX XXX+` and every `CNatural`), and the reading → ABC: equal notes
    (`L:1/4`, `M:none`), one ABC line per tab line, the whistle's major key,
    `%whistle_tab_key`, unknown fingerings as `"^?"z`.
  - `TabImageLoader`: picked image → `GrayImage` (longest side ≤ 2400).
- `audio/` — the tap editor's low-latency sound. `TapAudio` is the screen's
  one engine, open while it is resumed (`resume` + `open` off the main
  thread; `close` on pause frees the stream): it feeds one `PcmOutput` one
  burst at a time from the pure `TapMixer` (voices, the old one fading as a
  new one starts, plus metronome clicks between `startClicks` and
  `stopClicks`; every call only queues a command). When the output dies — an
  exclusive AAudio stream is disconnected whenever anything else plays, the
  preview's WebView included — the writer thread clears the engine (`alive`
  goes false) and the next `open` starts a fresh stream, so a tapper Start
  always gets a live one. The pad's samples render while the setup sheet is
  up and the metronome starts before any rendering left, so Start is
  instant. Palette taps and the
  pad's notes are samples rendered ahead at the output's rate; touch times
  become ms from the downbeat with the output's own timestamps. `openOutput` picks native AAudio
  (`AAudioOutput` over `NativeTapStream`, the JNI side of
  `app/src/main/cpp/tap_audio.c`, the app's only native code: it opens a
  low-latency, exclusive stream and writes chunks; all mixing stays in
  Kotlin) on Android 8.1+, else `AudioTrackOutput`. The writer thread owns
  the output once started and closes it.
- `data/settings/` — `TabSettingsStore` (DataStore, injected; enums stored by
  name, unknown names fall back to defaults); `SettingsDataStores` owns the
  process-wide instance. `AppGraph` in `WhistleTabberApplication.kt` is the
  manual DI root, with an `appScope` for work that outlives a screen.
- `data/tunes/` — Room (`AppDatabase`, `whistle-tabber.db`, schemas exported
  to `app/schemas/`, also served as debug assets for `MigrationTestHelper`).
  `TuneEntity.abc` is the canonical record; every other column is derived by
  `TuneIndex.apply` on each save (folded `searchKey`/`sortKey` make search and
  sorting case- and accent-insensitive). `TuneRepository` is the only way in
  from the UI and maps rows to `Tune` (`whistle` is the tune's own directive,
  else its key's suggestion; `explicitWhistle` is the directive alone);
  `importBook` skips a tune with the same
  title and the same music (`TuneIndex.sameMusic`). `TuneImporter` is the
  one way tunes come in: `importFiles(uris)` (one `ImportResult` for all
  files, unreadable files counted) and `addStarterSet()`, which imports
  `assets/tunes/oneills.abc` (10 well-known O'Neill's 1850 tunes, generated by
  `scripts/build-starter-set.sh` from `scripts/starter-tunes.txt`; never edit
  it by hand), plus `importText` for shared ABC text. Its `busy` covers
  every import, on any screen. `IncomingTunes` handles "Open with" and
  "Share" from other apps: `MainActivity` (`singleTask`; intent filters for
  `VIEW` on `content:` and `SEND`/`SEND_MULTIPLE`) turns the intent into
  `SharedTunes` and calls `receive`; `arrivals` makes `AppNavHost` pop to the
  library (not from the editor), and `LibraryViewModel` reports `result`,
  then `consume`s it. `PastedTunes` is the clipboard counterpart of
  `SharedTunes`: the library's Paste turns the clip into an image (routed to
  the scan screen), `content:` files and ABC text (imported as one result).
  `RecentlyDeleted` owns delete with undo: `delete(ids)` (or
  `delete(id)`) removes the rows in one transaction and puts them on `offer`
  as one batch (one batch at a time, newest wins); `undo`/`dismiss` answer
  it, and the restore runs on `appScope`.
- `assets/web/`
  - `whistle-core.js`: pure helpers, node-testable. `extractNotes` lists the
    first voice's written notes with MIDI pitch from abcjs's own audio
    sequence (`setUpAudio`), keyed by `startChar`.
  - `whistle-core.js` also owns diagram geometry (`diagramShapes`,
    `DIAGRAM_HEIGHT`), node-tested, and `transposeAbc(ABCJS, abc, steps)`:
    abcjs `strTranspose`, which needs the *array* from `parseOnly` (given a
    single tune it silently changes nothing). The page answers the stateless
    `transposeText {abc, steps}` command with `transposedText`.
  - `whistle-page.js`: DOM, playback and bridge. Renders with abcjs `wrap`
    at 1.2× the screen width (scaled down to fit). Draws each diagram inside
    its staff line's `<g>` under the line's lowest element, then pushes later
    lines down where diagrams would collide (`pushLinesApart`; abcjs's
    `staffsep` only counts note pitches). `B:`/`Z:`/`N:` credits go to HTML
    `#credits` below the SVG. `layoutReport()` exists for instrumented tests.
  - `index.html`: strict CSP, local scripts only.
- `ui/` — `theme/` (the "bottle green & brass" scheme, heavy headline
  type, rounded shapes, and `LocalWhistleColors` for the star and play
  colours; `assets/web/whistle.css` mirrors its ink, paper and highlight);
  `components/` (`Cards.kt`: `SectionCard`, `ScreenTitle`, `GroupLabel`,
  `PillChip`, the shared building blocks of every screen; `FingeringDiagram`, matching the page's
  diagrams, with `FingeringDiagramGeometryTest` pinning the shared geometry;
  `whistleLabel`, which reads the `LocalNoteNames` composition local that
  `MainActivity` provides from the settings store). `AppNavHost` holds type-safe `@Serializable`
  routes: `LibraryRoute` (start), `TuneRoute(id)`, `EditorRoute(id?, draft?)`,
  `SettingsRoute`, `FindTunesRoute`, `ScanTabRoute`, `TapEditorRoute(id?)`. Each screen has a ViewModel built from `AppGraph` and a
  stateless `…Content` composable where Compose tests need one.
  - `library/`: search, rhythm and Starred chips, the starter-set offer on an
    empty library, SAF import (through `TuneImporter`) and export
    (`data/tunes/AbcFiles`: UTF-8, else Latin-1), and Paste from the
    clipboard in the add-tune speed dial (`PastedTunes`: an image goes to
    the scan screen, files and text import through `TuneImporter`).
    Multi-select: a long press
    starts selecting (`LibraryUiState.selected`, only tunes the filters
    show), the top bar offers select all and delete. Deletes from here
    (`deleteSelected`) or the tune screen arrive as `RecentlyDeleted.offer`;
    the snackbar answers with `undo` or `dismiss`.
  - `tune/TuneViewModel`: the tune and its settings; the render cycle
    belongs to its `TuneRenderer`, the key-change preview to its
    `KeyChangePreview` (preview state and the copy's title). The tune's own
    whistle (`%whistle_tab_key`, else its key's suggestion) is the
    *written-for* whistle; `TabSettings.whistle` is *my* whistle. The
    ViewModel feeds `show(abc, midiTranspose, fingerings)` on every change
    and lets the renderer dedupe. Key change: `KeyChangePreview.start` →
    preview render → save as a copy (default) or replace.
  - `editor/`: draft in `SavedStateHandle`, preview rendered by its
    `TuneRenderer` (debounced 400 ms), save blocked without `T:`/`K:`. A new
    tune may start from a given draft (`initialText`, from the scan screen),
    unsaved until the user saves.
  - `scan/`: "Read tab from an image" (Library menu, `ScanTabRoute(image?)`;
    a pasted clipboard image is read on entry instead of opening the picker,
    and a Paste button adds one too): the photo picker
    (multi-select; later picks append), `TabReader` off the main thread,
    each image with its diagrams outlined (unknown fingerings in the error
    colour), title and written-for whistle; "Open in editor" passes
    `TabTune.toAbc` of the images' combined reading (`TabTune.combine`) as
    the editor's draft. Nothing is saved on this screen.
  - `tap/`: "Write with fingerings" (Library menu, `TapEditorRoute(id?)`):
    title, a strip of the tapped diagrams with a cursor, live preview with
    diagrams and playback, the written-for whistle, and a palette of
    fingerings (octave chips, the scale plus C natural, half-hole notes under
    "More"), rest, delete and cursor keys. A tap also sounds the note through
    `audio/TapAudio`. Draft (rhythm included) in `SavedStateHandle`; saves
    `TapTune.toAbc`. "Tap the rhythm" opens the rhythm
    tapper (`RhythmPanel`: the setup in a bottom sheet with a `PadSound` of
    note, tick or silent, then a press-and-hold pad over a metronome with a
    count-in bar, then keep or try again; files `RhythmPanel.kt`,
    `NoteStrip.kt`, `Palette.kt`). A pass of tapping is a pure `RhythmSession`
    (presses, the held one, a press while one is held ends it there); sound
    comes from `audio/`. While tapping, touches are delivered unbuffered
    (`Modifier.rhythmPad`): each finger that lands is a press, and only the
    newest finger's lift is a release. The kept rhythm becomes the draft's
    `TapTiming` (Cancel and Try again restore the draft from before the
    tapper opened; "Remove rhythm" drops it), renders and saves with it, so a
    timed tune stays tap-editable. The note strip shows bar gaps from the
    note lengths and a mark of each note's length. The audio diagnostics show
    in debug builds only; a release build warns when the delay is over 60 ms.
    The tune screen's Edit opens it when
    `TuneUiState.tapEditable` (`TapTune.parse` succeeds), with "Edit ABC" for
    the text editor; other tunes go straight to the text editor.
  - `findtunes/`: "Find tunes online", links (`TUNE_SITES`) opened in the
    browser with `ACTION_VIEW`; downloads come back through `IncomingTunes`.
    Never list TheSession.org (a test checks).
  - `settings/`: `TabSettingsContent` (shared with the tune screen's sheet),
    `TabSettingsEditor` (one owner for tab-settings writes; injected from
    `AppGraph`, exposed by both ViewModels), starter set, licences.
  Each screen with a WebView owns one `TuneWebController`, attaches it to its
  ViewModel's `TuneRenderer`, and destroys it on dispose.

Data flow for diagrams: page `rendered(notes)` → `TuneRenderer` →
`FingeringEngine.forNotes` → `DiagramSpec` list → `diagrams` command → page
draws. Notes are indexed identically on both sides (`extractNotes`).

The roadmap and session log live in `docs/ROADMAP.md`.
